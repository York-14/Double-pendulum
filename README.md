# Double Pendulum — Nature / Chaos / Symmetry

二重振り子（Double Pendulum）のカオス力学だけを数式的な源泉として、Web上でリアルタイムに生成されるジェネラティブアートです。

**Live**: https://double-pendulum-bay.vercel.app

背景は黒、描写物は淡いピンクと淡いブルー。ランダムに見える有機的な広がりの裏側には、すべて力学方程式と統計量から導かれる決定論的なロジックがあります。

## コンセプト

- **Nature** — 花・珊瑚・雪の結晶のような、自然物に宿る「対称性の中の揺らぎ」を志向する
- **モダンアートの美しさとシャープさ** — 黒背景 × 淡いピンク/ブルーの2色軸、加算合成による発光、輪郭のシャープな点描
- **数式で表せるランダム性・カオス性・対称性** — 乱数はほぼ使わない。すべて二重振り子の物理量とその派生値（カオス指標）から視覚パラメータを導く
- **唯一無二性** — 起動ごとに生成されるseed値が初期角度・対称数を決定する。カオス系の初期値鋭敏性により、同じ構造は二度と現れない

## パイプライン

```
Double Pendulum          RK4積分による二重振り子の状態更新
      ↓
Physical State            位置・速度・エネルギーの抽出
      ↓
Chaos Metrics              ゴースト振り子とベネッティン法によるリアプノフ指数(chaosIndex)
      ↓
Particle Field              chaosIndexを色・発生量に写像した粒子の生成
      ↓
Volumetric Structure     放射対称複製 + 3D空間でのレンダリング
```

以下、各層がどんな数理モデルで実装されているかを解説します。

---

### 1. Double Pendulum — `src/physics/DoublePendulum.js`

質点2つ・腕2本の二重振り子をラグランジュ力学の運動方程式で表し、状態ベクトル

```
state = [θ1, θ2, ω1, ω2]
```

を **4次のルンゲ=クッタ法（RK4）** で数値積分しています。オイラー法などの低次積分器では、カオス系特有の急峻な軌道変化に対して誤差が急速に蓄積し、エネルギーが発散してしまうため、この作品では精度と安定性を優先してRK4を採用しています（実測でエネルギードリフトは100秒の積分で 10⁻⁹ オーダー）。

各フレームでは実時間1/60秒を60回のサブステップ（dt = 1/3600秒）に分けて積分し、体感速度と数値安定性を両立させています。

### 2. Physical State

`DoublePendulum` から抽出される物理量：

- 質点1・質点2の直交座標（`getPositions`）
- 質点の速度ベクトル（`getVelocities`、位置の解析的な時間微分）
- 全エネルギー `E = T + V`（積分の妥当性検証にも使用）

これらは次の層（カオス指標・粒子生成）への入力になります。

### 3. Chaos Metrics — `src/chaos/ChaosMetrics.js`

「今この瞬間、系がどれだけカオス的か」を表すスカラー値 `chaosIndex ∈ [0, 1]` を、**ベネッティンのアルゴリズム**でリアプノフ指数を推定することで求めています。

1. メイン振り子から見て位相空間上に極めて近い初期値（距離 ε = 10⁻⁸）を持つ「ゴースト振り子」を並走させる
2. 一定ステップごとに、メインとゴーストの位相空間距離 `d = ‖state_ghost − state_main‖` を測定し、局所的なリアプノフ指数 `λ ≈ ln(d/ε) / (steps・dt)` を計算する
3. ゴーストの状態をメインから距離εまで引き戻す（再正規化）。そのままだと`d`が指数関数的に発散し、数値的な意味を失うため
4. `λ` をロジスティック関数 `1 / (1 + e^(−λ・sensitivity))` で `[0, 1]` に正規化し、指数移動平均で滑らかにしたものが `chaosIndex`

カオスが強い瞬間（軌道の発散が速い瞬間）ほど `chaosIndex` は1に近づき、秩序的な瞬間は0に近づきます。

### 4. Particle Field — `src/particles/ParticleField.js` / `src/render/color.js`

`chaosIndex` を軸に、物理量を視覚パラメータへ写像します。

| 視覚パラメータ | 由来 |
|---|---|
| 発生位置 | 質点2（先端）の座標 |
| 色 | `chaosIndex` を `HSL` 空間で淡いブルー（秩序側）⇔淡いピンク（カオス側）に線形補間 |
| 初速 | 質点2の実速度（頭打ちあり。詳細は後述） |
| 奥行きの初速 | ω1（x, y座標には現れない位相空間の成分）を写像 |
| 発生数/フレーム | `chaosIndex` に比例（カオスが強いほど密に生成） |
| 寿命・減光 | 生成時に乱数で決定、寿命に対する残り時間の割合で不透明度が減衰 |

> 二重振り子の瞬間速度はエネルギー保存の範囲内で理論上いくらでも大きくなり得るため、生の速度をそのまま初速に使うと稀に粒子が画面外まで飛んでいき、後述のカメラの自動フィット半径を際限なく押し広げてしまいます。そのため初速の大きさ（xy平面・奥行きそれぞれ）に上限を設けています。

### 5. Volumetric Structure — `src/render/VolumetricRenderer.js`

Three.js / WebGLで3D空間にレンダリングします。

- **放射対称複製**：起動時のseedから対称数 `N`（6〜12回）とミラーの有無を決定論的に導出し（`src/core/Seed.js`）、1系統ぶんの粒子データをY軸まわりに `360°/N` ずつ回転複製する。物理演算は1系統だけで済ませ、対称性は幾何変換だけで作る設計
- **オートフィットカメラ**：毎フレーム、粒子群の中心Yと軸からの最大半径を計測し、縦・横それぞれの画角で構造がちょうど収まる距離を計算してカメラを滑らかに追従させる（縦長のスマホ画面と横長のデスクトップ画面の両方で破綻しないよう、垂直・水平FOVそれぞれの必要距離のうち大きい方を採用）
- **Fog / 粒子サイズのカメラ距離補正**：カメラが構造に合わせて遠ざかっても、Fogの濃度と粒子サイズをカメラ距離に応じて動的に補正し、画面全体が黒に沈んだり粒子が見えなくなったりしないようにしている
- **Bloom**：`UnrealBloomPass` による加算合成の発光効果で、輪郭はシャープに・光は滲むように

カメラは常時ゆっくり周回し、静止画ではなく「空間の中にいる」没入感を出しています。

## 唯一性の担保

起動ごとに `seed = Date.now() XOR random32` を生成し、対称数・ミラー有無・初期角度をこのseedから決定論的に導出します（`mulberry32` による擬似乱数生成器）。同じseedなら理論上は同じ構造が再現されますが、二重振り子は初期値に対して指数的に鋭敏（カオス）なので、わずかに異なるseedは時間経過とともに全く別の構造へ発散していきます。

## 自己修復性

数値発散（非数化）を検知した場合は対称パラメータを保ったまま物理状態だけを新しいseedで仕切り直し、1フレームの例外でアニメーション全体が止まらないよう描画ループを保護しています。カオスと生成のサイクルが止まらないことを、実装レベルでの設計方針としています。

## ディレクトリ構成

```
src/
  physics/DoublePendulum.js   RK4積分・状態量・エネルギー
  chaos/ChaosMetrics.js       ゴースト振り子 + ベネッティン法 → chaosIndex
  particles/ParticleField.js  粒子の生成・寿命管理
  render/color.js             chaosIndex → ピンク/ブルーのHSL補間
  render/VolumetricRenderer.js Three.jsシーン、対称複製、オートフィットカメラ、Bloom
  core/Seed.js                 seed → 対称数・初期角度の決定論的導出
  main.js                      オーケストレーション（毎フレームのループ）
```
